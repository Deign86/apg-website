# src/routes/admin/

## Responsibility

Implements the authenticated `/admin/*` application: sign-in, dashboard, content and portfolio CRUD, recruitment pipeline with ATS screening, user administration, and live-chat operations.

## Design

- `AdminShell` provides nested React Router routes inside `AuthProvider`; `/admin/login` is public, while dashboard and module routes share `ProtectedRoute` around `AdminLayout`. `admin.css` supplies admin-specific styling. On an enterprise subdomain in production, `App.jsx` redirects `/admin` to the apex. `Login` and `Dashboard` ship with the shell; every manager screen is a lazy chunk (`AdminLayout` shows a spinner in its `Suspense`), and `PrefetchScreens` loads the screens the signed-in role may open once the browser is idle. Unmounting `AdminShell` calls `clearListCache()` so public pages opened afterwards reload lists edited here.
- `ProtectedRoute` waits for session loading, then redirects unauthenticated users to `/admin/login`. `AuthProvider` verifies/signs in/out through `/api/admin/auth.php` and exposes `user`, `can`, and session state.
- `Dashboard` greets the user, links to each module, and loads summary counts concurrently from admin endpoints. `Login` invokes `signIn` and navigates into `/admin`.
- Managers use component-local state and direct `fetch` calls with `credentials: 'include'`, not the public data hooks. Shared admin components: `PageHeader`, `SegmentedControl`, `EnterpriseSelect`, `useToast`, `ConfirmDialog`, `DataTable`, `StatusPill`, `EmptyState`; capability checks use `useAuth().can(...)`.
- Visual direction ("quiet workspace"): site palette and font via `admin.css` tokens, gold only for the brand, one primary action, selected state and work needing attention (`.admin-row-new`, Dashboard `is-attention` cards); no blue tone; filter rows are `.admin-toolbar` (enterprise select + segmented status + `.admin-search`). Only `Login` uses the public site's card/pill classes (kept by `__tests__/site-alignment.test.mjs`).
- `ApplicantsManager` defines an `AtsBadge` (`<score>/100`; green when `ats_shortlisted`, amber when `ats_details.recommendation === 'maybe'`, red otherwise, "Pending" when unscored) shown in an ATS Score column and in the detail panel, which also lists `ats_details` summary, strengths, gaps, matched keywords, and method (AI vs keyword scored).
- `BlogManager` and `ContentEditor` render HTML live previews through `DOMPurify.sanitize(...)` (replacing the earlier regex sanitizer).
- `LiveChat` labels bot messages "APG Assistant".

## Flow

1. `App.jsx` routes `/admin/*` to `AdminShell` → `AuthProvider` → `Login` at `login`, or protected `AdminLayout` outlet for index (Dashboard), `live-chat`, `content`, `services`, `careers`, `applicants`, `blogs`, `users`; unknown protected paths render admin `NotFound`.
2. Session bootstrap checks `/api/admin/auth.php?action=check`; `Login` POSTs credentials; sign-out uses `?action=logout`. Controls call `can('content'|'services'|'careers'|'applicants'|'blogs'|'delete')`; server authorization remains authoritative.
3. `Dashboard` concurrently reads `/api/admin/` `services.php`, `careers.php` and `content.php` (lists), counts from `applicants.php?action=summary`, `blogs.php?per_page=1` (`total`), `chat.php?summary=1` and `inquiries.php?action=summary`, plus the public `/api/listings.php`.
4. CRUD/API mapping:
   - `BlogManager` ↔ `/api/admin/blogs.php`: GET list (no article bodies); GET `?id=` fills the body when the editor opens (the body field and Save stay disabled until it loads, since PUT sends the whole form); POST; PUT; PATCH `{ id, status }`; DELETE `?id=`; `?action=upload_image` for covers.
   - `CareerManager` ↔ `/api/admin/careers.php`: GET; POST; PUT update/status; DELETE `?id=`.
   - `ServicesManager` ↔ `/api/admin/services.php`: GET all or `?category=`; POST; PUT update/publish; DELETE `?id=`.
   - `ApplicantsManager` ↔ `/api/admin/applicants.php`: GET 50 rows at a time with server-side filters (`enterprise`, `status`, `shortlisted`, debounced `search`) and `sort=score`; "Load older applicants" continues after the last row (`before_at`/`before_id`, plus `before_score` when sorted by score); enterprise counts come from `by_enterprise` and the new badge from `summary`; opening a row loads the full record from `?id=` (detail sections and notes wait for it); PUT status or notes; DELETE `?id=`; link `?action=resume&id=` opens the protected resume; POST `?action=rescreen` `{ id }` (gated by `can('applicants')`) re-runs ATS scoring and merges the returned `ats_*` fields into the row and detail panel with a toast.
   - `ContentEditor` ↔ `/api/admin/content.php`: guided registry editor (page picker from `CONTENT_SCHEMA`, labeled fields per section, Customized/Unsaved badges, reset-to-default, repeaters, image upload+URL, richtext preview, unsaved-changes guard); GET `?page=`; POST `{ page_slug, values }` (batch, validated) or superadmin `{ page_slug, raw }` (Advanced raw keys view); DELETE `?page=&key=` (reset); `?action=upload_image`. `_private` (inboxes, chat notes) needs `private_settings` (superadmin/admin).
   - `UsersManager` ↔ `/api/admin/users.php`: GET; POST; PUT; DELETE `?id=`.
   - `LiveChat` ↔ `/api/admin/chat.php`: GET `?status=open` (open queue, polled whole); closed history 50 at a time (`?status=closed&limit=&offset=`, "Load older", debounced server search `q`); GET `?session_id=` thread, then `&after_id=` for only the newer messages; POST `{ action: 'message'|'claim'|'close', session_id, ... }`. Queue and thread poll every 3.5s while the tab is visible (and once when it returns); a `session` query param preselects a thread.
5. Mutations show toasts and reload or patch the affected collection; destructive actions use `ConfirmDialog`. Applicants filter by enterprise, status, search, and a "Shortlisted" toggle, and sort by newest or highest ATS score (unscored last), all server-side. `DataTable` is used by blog and user managers.

## Integration

- Depends on `src/context/AuthContext.jsx`, `src/data/permissions`, `src/components/admin/*`, and `src/data/enterprises` (`ENTERPRISE_TABS`/`ENTERPRISES` for enterprise filters/options); also `dompurify`, `lucide-react`, and React Helmet metadata.
- PHP endpoints under `/api/admin/` are the authenticated persistence boundary. Uploads use multipart form data; other writes send JSON with HTTP verbs. ATS scores are produced server-side (keyword or optional Gemini scoring) when public applications arrive via `/api/applicants.php` or on re-screen.
- Admin records feed the public site's display readers (`useCareers`, `useServices`, `useContent`, blog lists), which the managers do not call. Property listings come from the APR Google Drive; `ListingsManager` (`/admin/listings`, capability `listings`) ↔ `/api/admin/listings.php` (GET feed incl. hidden + overrides + sync status; PUT per-ref hide/feature/order/price override/note) and shows the Drive sync status banner. `InquiriesManager` (`/admin/inquiries`, capability `inquiries`) ↔ `/api/admin/inquiries.php` (filtered list 50 rows at a time, "Load older" continuing from the last row's `before_at`/`before_id`; list rows omit `meta.replies`, which the `?id=` detail carries; detail, status PUT, DELETE, `?action=export` CSV, `?action=summary` unread counts used by the Dashboard card); Inbox and Newsletter tabs, whole-row click opens the detail drawer, in-drawer reply (`POST ?action=reply`, shows `meta.replies`) with a mailto fallback.
