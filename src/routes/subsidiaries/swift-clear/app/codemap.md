# swift-clear/app/
## Responsibility
- Implements SwiftClear's page switcher, themed UI, services, blog feed/details, careers, and inquiry.
- `App.tsx` contains shared elements and FrontPage, Home, Services, Blogs, BlogDetail, Careers, CareersForm, and Inquire views.
- Blog types, caching/loading, and offline fallback rows are maintained in the app module.
- `components/` contains a Figma image-fallback utility that App does not import.
- The standalone `main.tsx` entry one directory above is not referenced by the build.
## Design
- Pages use a blue/white palette with Tailwind utilities and Motion effects.
- `SanitationParticles`, `BgDecor`, and `Navbar` are shared in-file helpers; `Navbar` returns null when embedded.
- Utilities are generated by the corporate global Tailwind build, since the route does not import `../styles`.
- Blog markdown-ish lines are converted to HTML and passed through `DOMPurify.sanitize` before rendering.
- Embedded mode (with `setPage`) switches views by key; without it, a `BrowserRouter` route tree is used.
## Flow
- Parent props control the current page and provide navigation callbacks in embedded mode.
- Home and Services use `useServices`; Careers uses `useCareers` and an in-page application form.
- `useBlogs` queries the SwiftClear API, caching results and retaining bundled offline articles.
- Selecting a blog or position swaps to the detail/form view via local state.
- Inquire and career forms send `form_started_at`, show sending state, and surface server/network errors.
## Integration
- App imports logo/background images from `../imports/SwiftClearBlogs` and `../imports/SwiftClearFrontPage`.
- Blog data comes from `/api/blogs.php?enterprise=swiftclear`; services/careers hooks come from `@/hooks`.
- Inquiries POST JSON to `/api/inquire.php`; applications POST multipart to `/api/applicants.php`.
- `SwiftClear.jsx` owns enterprise context, `EnterpriseSeo`, and page synchronization.
- `BlogRecord` is the exported local content contract for feed and detail rendering.
