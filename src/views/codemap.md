# views/

## Responsibility
Tab-level React views rendered by `RedesignShell` for the public APG landing page, enterprise portfolio, editorial blog, careers catalog/application portal, and inquiry form.

## Design
- `HomeView` combines static `ENTERPRISES`, `PROPERTY_TYPES`, and `CORE_VALUES` from `companyData.ts` with copy from `useContent('home', fallback)`, and composes `AboutUsSection`, `EnterprisesGallery`, and `SeamlessHeroVideo`. Category cards are keyboard-operable (`role="button"`, Enter/Space, `aria-expanded`). Its decorative background loops are CSS classes from `styles/apex-motion.css` (compositor-only); `useOffscreenPause` marks a section `data-offscreen` while it is out of view (IntersectionObserver), which pauses them.
- `EnterprisesView` presents the division profiles and delegates inquiry through `onOpenInquire`; full-site buttons navigate to `/subsidiaries/<slug>`. Editorial blocks animate from scroll position (`motion/react`), with `will-change` only while a reveal runs; logos are small WebP variants (`/assets/images/logos/`) and photos load lazily.
- `BlogsView` starts with typed `BLOG_POSTS` fallback (or the session-cached list) and maps successful `/api/blogs.php?summary=1` records (no `content`; every field checked as text) into `BlogPost` cards plus slug and company. It renders 12 cards and "Load more" adds 12 at a time; a category or search change resets to 12. Search (labelled `#blog-search`) and category filtering are local state. Each card's title is a real `<Link to="/blogs/<slug>">` stretched over the card (plain click navigates in-app, modified clicks open a tab).
- `BlogsView` also renders every company's article page at `/blogs/:slug` (`useMatch`; same chunk, and the list state survives, so Back finds the filters and "Load more" as they were): the post from `/api/blogs.php?slug=` (kept for the session), an `<h1>`, company, date, read time, cover, the body via `components/BlogBody`, an inquire CTA, a link back to `/blogs` and 3 related posts (same company first), with head tags from `lib/blogSeo`. A loading status shows meanwhile, a failed request a "could not be loaded" heading; an unpublished/unknown slug renders the list under an "isn't available" notice with `noindex`. Old shared links `/blogs?post=<slug>` redirect to the article.
- `CareersView` starts with `OPEN_POSITIONS` and maps `/api/careers.php` records (session-cached via `lib/listCache`) to `JobOpening` (`lib/jobSeo`: `JobPosition` + `created_at`; text-only list items, default responsibilities/requirements/perks). It keeps an inline application form (ids/`name`s, `aria-invalid`/`aria-describedby` errors), division/search filters, and a testimonial "feedback" dialog wired to `useModalDialog`; submitted testimonials are only prepended to local state. Each live opening's title links (real `<a href>`) to its own page.
- `JobView` (rendered by `CareersView` on `/careers/{id}[-{slug}]`) is one opening's page: company, title (`<h1>`), location/type/salary, description, responsibilities, requirements and "Apply" links to `/careers/apply?job=<id>`, with its own `<Seo>` from `jobSeo()` (canonical, title, description, `JobPosting` JSON-LD). A missing/outdated slug is replaced by the canonical one; a closed or unknown id shows "This position is no longer open" + the open positions (noindex); a failed load shows a retry message with the careers page metadata. It renders no `<h1>` while loading (`main.jsx` hands off from a crawler snapshot on the first one).
- `InquireView` uses `ENTERPRISES` to populate the division selector and keeps inquiry fields, submission/loading/error state and ticket reference locally.

## Flow
- `HomeView` → `useContent('home', ...)` → `/api/content.php?page=home` merged over fallback → hero, mission/vision, CEO quote, FAQ render. CTA calls `onOpenInquire`; enterprise actions call `onNavigate` or `onSelectEnterprise`.
- `BlogsView` → `fetchList('/api/blogs.php?summary=1')` (once per session) → records replace fallback → filtered by category/search → first `visibleCount` cards → a card link navigates to `/blogs/<slug>` → `fetch('/api/blogs.php?slug=')` → article + `<Seo {...blogSeo(post)}>` (404 → the list with a noindex notice). Crawlers get the same pages as server HTML from `api/blog-page.php`.
- `CareersView` fetches `/api/careers.php` once per session (`lib/listCache`; a revisit starts from the cached rows) → rows replace `OPEN_POSITIONS`. A job path (`jobIdFromPath`) renders `JobView` from those rows. Otherwise the route drives the form: `?job=<id>` or `?job=general` / `/careers/apply` selects a role or general application; returning to `/careers` (incl. Back/Forward) clears the form. Submit builds multipart `FormData` (candidate fields, job metadata, honeypot/timestamp, optional resume) → POST `/api/applicants.php` → ticket or error. It takes no props (the old `onApplyJob`/`onGeneralApply` modal path was removed).
- `InquireView` collects contact, enterprise, budget, timeline, and message → POSTs JSON to `/api/inquire.php` → `success === true` shows the ticket confirmation; otherwise the server's `error` string (or a fallback message) populates the error state.
- `EnterprisesView` has no API fetch.

## Integration
- `RedesignShell` lazy-loads each view as its own chunk and mounts it by tab (`home`, `enterprises`, `blogs`, `careers`, `inquire`) and owns their SEO via `components/Seo` (careers: `CAREERS_SEO` from `lib/jobSeo`); the views render no head tags, except `JobView` on a job page and `BlogsView` on a blog article (`/blogs/<slug>`), where the shell renders none. Crawlers get the careers page and each job page as server HTML with the same head (`api/careers-page.php`, `api/lib/JobPages.php`) and find them in `/sitemap-jobs.xml`.
- Shape sources: `BlogPost`, `JobPosition`, `Enterprise`, `NavTab` types plus `companyData.ts` fixtures. Of the data hooks only `useContent` is used here; `BlogsView` and `CareersView` fetch through `lib/listCache` (`peekList`/`fetchList`). `useModalDialog` backs the careers feedback dialog.
- Career applications submit to `applicants.php` (server ATS screening happens there); inquiries submit to `inquire.php`.
