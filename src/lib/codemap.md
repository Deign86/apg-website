# lib/

## Responsibility
Client-side utilities: the chat API/session-token client used by the enterprise chatbot (`ai.js`), hostname-based enterprise subdomain helpers (`enterpriseHost.js`), and the session cache for public list endpoints (`listCache.ts`).

## Design
- `ai.js`:
  - `getSavedSessionToken()` / `saveSessionToken(token)` read/write the `apg_chat_session_token` key in `localStorage`; storage failures are caught and treated as unavailable.
  - `startChatSession(enterpriseSlug = 'apg-main', sessionToken = null, restoreOnly = false)` creates or restores a session and persists a returned token; with `restoreOnly` an ended session is not replaced and the result is `{ success: false, closed: true }`.
  - `sendChatMessage(sessionToken, message, enterpriseSlug = 'apg-main', isHandoff = false)` sends a visitor message or live-agent handoff.
  - `pollChatSession(sessionToken, afterId = 0)` retrieves session status, assignment, and newer messages.
- `enterpriseHost.js` (imports `ENTERPRISE_SLUGS`; subdomain slugs are all except `corporate`):
  - `ROOT_DOMAIN` (`alphapremiergroup.com`), `basePathFor(slug)` (`/virtual-office` for virtual-office, else `/subsidiaries/<slug>`), `enterpriseOrigin(slug)` (`https://<slug>.<ROOT_DOMAIN>`).
  - `hostEnterprise(hostname?)` returns the enterprise slug served by a `<slug>.<ROOT_DOMAIN>` host, or `null` on apex/www/other hosts. `isProductionHost(hostname?)` is true for the apex and any subdomain.
  - `enterpriseFromPath(pathname)` splits an in-app path into `{ slug, rest }` when it belongs to an enterprise, else `null`.
  - `MAIN_SITE_HREF` is `https://<ROOT_DOMAIN>/` on an enterprise subdomain, otherwise `/`.

- `formValidation.ts`: `nameError`, `emailError`, `phoneError(value, required)`, `textError(value, {label, required, min, max})`, `urlError`; each returns a short message or `null`. Every public form validates with these; `api/lib/Validation.php` mirrors the rules and messages.
- `applicantExtras.ts`: per-opening application extras. `jobRequiresPhoto` / `jobAsksPortfolio` read the 0/1 `require_photo` / `ask_portfolio` flags; `photoFileError(file)` checks a 2x2 photo (JPG/PNG, <= 5 MB, square within 3%, >= 600x600 via `photoDimensionError`); `parsePortfolioLinks` / `portfolioLinksError` (optional, <= 5 http(s) URLs). The form UI is `components/careers/ApplicantExtrasFields.tsx`; `api/applicants.php` enforces the same rules.
- `listCache.ts`: one request per URL per page session for list endpoints that return `{ success, data: [] }`. `peekList(url)` returns rows already loaded (for a first render); `fetchList(url)` resolves the `data` rows, shares one in-flight request between callers, and rejects on a network/HTTP error or `success !== true` (a failure is not cached, so the next call retries); `clearListCache()` drops every list.
- `listingSeo.ts`: `listingSeo(listing)` returns the `<Seo enterprise="realty">` props for one listing's page: `path` `/properties/<ref>`, title `<title> (<size>) | Alpha Premier Realty`, a description of title/size, price and terms (trailing periods dropped, cut at a word to 160 code points), the first photo as `image`, and `RealEstateListing` + `BreadcrumbList` JSON-LD with empty values left out. `hubSeo(hub, hubs)` returns the same props for a browse page: the hub's `path`, `title` and `description`, `noindex` when it is not indexable (fewer than 3 listings), no image (default og-image), and a `BreadcrumbList` (Alpha Premier Realty › Available Properties › the type + deal hub, on an area hub when the feed has it › the hub). The crawler snapshots render the same tags server-side; unit-tested in `tests/unit/listing-seo.test.mjs`.
- `blogSeo.ts`: `blogSeo(article)` returns the `<Seo>` props for a blog article's own apex page (any company's post): `path` `/blogs/<slug>`, title `<title> | <company>` (`blogCompany(slug)`: names from `data/enterprises.js`, corporate/unknown = Alpha Premier Group, author URL = the company's site origin), the excerpt (else the body as plain prose, else the title) cut at a word to 160 code points, the absolute cover as `image`, and `BlogPosting` (headline ≤ 110, Manila dates as `+08:00`, dateModified falling back to datePublished, publisher = the group's `#organization`) + `BreadcrumbList` (Alpha Premier Group › Blogs › the article) JSON-LD with empty values left out. `blogArticleUrl(slug)` is the canonical URL (SwiftClear's own article view points its canonical there). `api/blog-page.php` renders the same tags for crawlers; unit-tested in `tests/unit/blog-seo.test.mjs`, parity with PHP in `tests/api/blog-pages.test.mjs`.
- `chatLayout.ts`: `splitListingRun(line)` turns a chat line that runs two or more `[APR-XXXXXX]` listings together into an intro line, one `- ` line per listing and a closing paragraph; other lines (and existing list items) come back unchanged. Used by `components/ChatText.tsx` (visitor widget and admin Live Chat); unit-tested in `tests/unit/chat-layout.test.mjs`.

## Flow
- Chat: saved token → `startChatSession` POSTs `/api/chat/start.php` (`session_token`, `enterprise_slug`, `restore_only`) → token saved. Input/handoff → `sendChatMessage` POSTs JSON to `/api/chat/message.php` (server answers with Gemini grounded in a knowledge base, FAQ fallback, or handoff) → result returned. Polling → `pollChatSession` GETs `/api/chat/poll.php?session_token=...&after_id=...`. All helpers return `{ success: false, error }` on caught failures rather than throwing.
- Hosts: `App.jsx`'s `useEnterpriseHostLocation` calls `hostEnterprise()` once at module load, maps clean subdomain paths with `basePathFor`, and (only when `isProductionHost()`) redirects using `enterpriseFromPath` + `enterpriseOrigin`. Localhost and preview hosts get `null`/false, so plain path routing applies.

## Integration
- `ai.js` consumer is `components/EnterpriseChatbot.jsx`, which owns UI, polling cadence, and chat state. Admin chat capability is `roleCan(..., 'chat')`; enforcement is server-side.
- `enterpriseHost.js` consumers: `src/App.jsx`, `components/Seo.tsx` and `listingSeo.ts` (`ROOT_DOMAIN`, `enterpriseOrigin` for canonicals/JSON-LD), Realty's `ListingCard` (`hostEnterprise` for `realtyHref`, the host-aware Realty link/navigation path), and `MAIN_SITE_HREF` in `components/EnterpriseHeader.jsx` and `routes/subsidiaries/alta-venture/Header.jsx`.
- Lead flows (`/api/inquire.php`, `/api/applicants.php`) validate fields with `formValidation.ts`; every apply form uses `applicantExtras.ts` through `useApplicantExtras`.
- `listCache.ts` consumers: `hooks/useServices`, `hooks/useCareers`, `views/BlogsView`, `views/CareersView`, `routes/subsidiaries/blogApi.ts`; `routes/admin/AdminShell` calls `clearListCache()` on unmount so public screens reload lists edited in the console.
- `jobSeo.ts` (job opening pages, `https://alphapremiergroup.com/careers/{id}-{title-slug}`): `jobSlug(title)` (ASCII letters/digits lowercased, other runs `-`), `jobPath(job)`, `jobIdFromPath(pathname)` (`/careers/39`, `/careers/39-any-slug[/]`, else null), `hiringOrganization(slug)` (name from `data/enterprises.js`, site origin, logo as `ENTERPRISE_META` in `components/Seo.tsx`; corporate/unknown = Alpha Premier Group of Companies), `CAREERS_SEO` (the `/careers` page metadata, used by `RedesignShell`), and `jobSeo(job)`: `<Seo>` props with title `<title> – <company> | Careers`, the description on one line cut at a word to 160 code points, and `JobPosting` JSON-LD (escaped HTML description with Responsibilities/Requirements lists, identifier, `datePosted` from Manila `created_at` as `+08:00`, `employmentType` from the free-text type, `hiringOrganization`, the group office for Ortigas/Pasig else the locality, `TELECOMMUTE` for remote/WFH, `directApply`; no salary or validThrough). Consumers: `views/JobView`, `views/CareersView`, `components/redesign/RedesignShell`. `api/lib/JobPages.php` builds the same head for crawlers (`api/careers-page.php`) and the sitemap URLs; `tests/unit/job-seo.test.mjs` checks both agree.
