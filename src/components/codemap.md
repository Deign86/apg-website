# src/components/

## Responsibility
Shared site chrome and cross-cutting components: enterprise-specific `EnterpriseShell` chrome, the shared AI/live chatbot, per-page SEO metadata (`Seo.tsx`), the cookie-consent banner, and the legacy `Header.css`/`Footer.css` stylesheets.

## Design
- `EnterpriseShell` is the shared subsidiary layout: `EnterpriseNavProvider` wraps `EnterpriseHeader`, routed `<Outlet />`, `EnterpriseFooter`, and `EnterpriseChatbot`.
- `EnterpriseHeader`/`EnterpriseFooter` resolve tenant branding and content through `getEnterpriseConfig(pathname)` and both navigate through `useEnterpriseNav().navigate(key)`; when it returns `false` (no enterprise page mounted, e.g. `/subsidiaries/<slug>/inquire`) they router-navigate to `/subsidiaries/<slug>` and the pending key is applied when that page registers. Header's parent badge links to `MAIN_SITE_HREF`; its menu toggle is a real `<button>` with `aria-expanded`/`aria-controls`, Escape closes the menu, and active items get `aria-current="page"`. Icons are lucide (`Menu`/`X`) and footer socials use `redesign/SocialIcon`; the site no longer loads Font Awesome.
- `Seo.tsx` is the single source of head metadata. Default `Seo({ title, description, path, enterprise?, image?, noindex?, jsonLd? })` renders title, description, absolute canonical (or `robots noindex, follow`), Open Graph, Twitter card, and one `@graph` JSON-LD block. Canonicals use the apex origin, or the enterprise subdomain origin (`enterpriseOrigin(slug)`) when `enterprise` is set, so they are identical whether reached by apex path or subdomain. `EnterpriseSeo({ slug, page })` looks up per-enterprise meta (title, description, logo, schema type, routed sub-pages); sub-pages without their own URL canonicalize to the enterprise home. Exports `ORGANIZATION_JSONLD` (with `subOrganization` per enterprise) and `WEBSITE_JSONLD`.
- `CookieConsent` reads/saves the choice through `src/lib/consent.ts` (shared `apg_consent` cookie on `.alphapremiergroup.com`, legacy `localStorage` key migrated), themed per enterprise, and renders nothing on `/admin*` (no choice saved there). It renders a `role="dialog"` banner with Accept All / Decline and a dismiss button (dismiss = decline), linking to `/privacy`.
- `EnterpriseChatbot` has internally controlled open/input/session/status state; it resolves title/accent/prompts/slug from enterprise config, restores a saved token (while the widget is closed only an open session, via `restoreOnly`; an ended one is forgotten), starts/polls sessions via `@/lib/ai`, supports explicit live-agent handoff, resets chats, and creates downloadable PDF transcripts with `jspdf`, imported on demand (warmed on pointer/focus of the download button). Replies come from the server (`/api/chat/message.php`, Gemini-backed and grounded in a knowledge base, with FAQ fallback). It portals into `document.body`; `EnterpriseChatbot.css` hides `.luxe-chatbot-wrapper` while any dialog is open (`html[data-modal-open]` from `useModalDialog`, or any `[aria-modal="true"]` element via `:has()`), and `EnterpriseHeader.css` drops the header to z-index 40 under the same condition; on phones the closed launcher also hides while a page `<form>` has focus.
- Legacy: `Header.css` and `Footer.css` have no component in this folder; they remain only as base styles imported by `routes/subsidiaries/alta-venture/Header.jsx` and `Footer.jsx`.

## Flow
- `EnterpriseShell` jumps to the top instantly on pathname change (`useLayoutEffect`, before paint; no AOS), then installs the nav provider so child enterprise views and header/footer share current page/navigation state.
- `EnterpriseChatbot` maps path to config/slug → restores an open session (or starts one when the widget opens) → maps server messages to display messages → polls `poll.php` by last message id (3s open, 5s closed/hidden) and reconciles optimistic visitor messages one-for-one → after a send, fetches the persisted bot reply via an immediate poll instead of appending `res.reply`. Unread admin messages increment a badge while closed.
- Route pages and shells render `<Seo>`/`<EnterpriseSeo>`; Helmet merges the tags into `<head>`.

## Integration
- **Consumers/routes:** `src/App.jsx` uses `EnterpriseShell` for Realty, Luxe Prime, Dynamic Tree, SwiftClear, Construction, and 88Prime routes and lazy-loads `CookieConsent`. `AlphaAssistant` (redesign) wraps `EnterpriseChatbot`. `Seo` is used by `RedesignShell`, `Contact`, `Properties`, `NotFound`, `PrivacyPolicy`, `TermsConditions`; `EnterpriseSeo` by `VirtualOffice` and every subsidiary page plus `EnterpriseInquire`.
- **Dependencies:** `src/context/EnterpriseNavContext`; `src/data/enterpriseConfig` (`getEnterpriseConfig`, `DEFAULT_ENTERPRISE_CONFIG`); `src/data/enterprises` (`ENTERPRISES` names for JSON-LD); `src/lib/enterpriseHost` (`MAIN_SITE_HREF`, `ROOT_DOMAIN`, `enterpriseOrigin`); `@/lib/ai`; React Router; `react-helmet-async`; `jspdf` (dynamic import); `lucide-react`; `redesign/SocialIcon`; component CSS files.
- `careers/ApplicantExtrasFields.tsx`: `useApplicantExtras(job)` (photo + portfolio state, `validate()`, `append(formData)`; resets when the opening changes) and `<ApplicantExtrasFields>` (renders the 2x2 photo / portfolio fields only when the selected opening asks for them, styled with the host form's classes). Used by every job application form (apex `views/CareersView`, `redesign/JobApplyModal`, and each enterprise careers page).
