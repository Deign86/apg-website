# api/

## Responsibility

Provides the public PHP REST endpoints, shared API configuration/PDO connection, and the schema plus dev/operator setup and migration tools. Public reads serve CMS content, jobs, services, blogs, and real-estate listings; public writes accept inquiries and applicant submissions (applicants are ATS-scored after the response).

## Design

- `config.php` loads root `.env`/`.env.local`, sets Manila timezone, starts the PHP session with strict settings (`httponly`, `use_only_cookies`, `use_strict_mode`, `SameSite=Lax`, `secure`) only for scripts in `api/admin/` (a session's file lock serialized a visitor's parallel calls; every other endpoint sends `Cache-Control: no-store` and sets no cookie), and defines `DB_*`/`SMTP_*`/`MAIL_*` constants. Helpers:
  - `sendJson()` — status + JSON body; no CORS headers (same-origin in production, Vite proxy in dev).
  - `guardPublicFormSubmission()` — honeypot `website`, required `form_started_at` (3 s–4 h elapsed), and `rateLimit('form-<ip>', 5, 600)`.
  - `rateLimit($bucket, $max, $window, $record = true)` — sliding window in a `flock`'d temp file per bucket; `$record = false` only checks (used to count failures).
  - `requireSameOrigin()` — CSRF guard for the cookie-authenticated admin API: a non-GET request must name the apex/www/current host or localhost in `Origin`, or (Origin absent) in `Referer`; neither header → 403. Public forms don't call it (no session authority; protected by `guardPublicFormSubmission()`).
  - `jsonBody()` (decoded JSON body, always an array) and `inputText($source, $key, $default)` (trimmed text; array/object → 422) for request input.
  - `webRootDir()` — `public/` in dev, the docroot in production (upload and logo paths).
  - `requireAdminAuth()` (session check + same-origin + role re-read from `admins` each request via `currentAdminRole()`; deleted admins are logged out by `destroyAdminSession()`; on GET it then calls `session_write_close()` so the admin's parallel requests don't queue on the session lock), `adminCapabilities()`/`requireAdminCapability()`/`requireSuperadmin()`, `enterpriseSlugs()`/`resolveEnterpriseSlug()`, and `requireSetupToken()` (CLI, or `X-Setup-Token` header only; otherwise 404).
- `db.php:getDbConnection()` memoizes a MySQL PDO connection (`utf8mb4`, exceptions, associative fetches, native prepares, session `time_zone = '+08:00'` so `NOW()`/`CURRENT_TIMESTAMP` DATETIMEs are Manila time like PHP's `date()` and the admin's `+08:00` parsing); failure returns `null` for endpoint-specific fallback. Native prepares forbid reused named placeholders, so multi-column searches bind `:search1..4`.
- Public read routes are GET-only and type-check query strings: `blogs.php` (published `blog_posts`, `?slug=` or enterprise filter; `?summary=1` lists without `content` except for posts with no excerpt, and `?slug=` returns the body), `careers.php` (active `job_openings`; `jobSchemaEnsure()` runs only when the query fails on a missing column), `content.php` (`content_blocks` values for one registered page, card JSON parsed; `_`-prefixed private pages are rejected), `services.php` (published `service_items`, each with `kind` service | product | package), `listings.php` (available properties from `data/listings.generated.json`, written by `cron/drive-sync.php`, merged with admin `listing_overrides` via `lib/Listings.php`: hidden refs dropped, `price_override` applied, `featured` first then `sort_order` then feed order; strips the staff-only `drive_folder`; empty list before the first sync, never sample data). Crawler pages from the same public view: `properties-page.php` (root `.htaccess` rule 0 serves it to bot user agents at `realty.alphapremiergroup.com/properties[/APR-XXXXXX | /{type}-for-{deal}[/{area}]]`) renders the index, one listing or one browse page (`?listing=` ref or hub path) into the docroot `index.html` shell, the shape `tools/prerender.mjs` snapshots have (`lib/CrawlerPage.php`, shared by all three crawler pages): default `data-rh` head tags swapped for the page's (title, description, canonical, OG/Twitter, one JSON-LD `@graph` with `RealEstateListing` + `BreadcrumbList`, matching the SPA's `Seo.tsx` output) and the content in `#prerender`; a gone or hidden ref is 410 `noindex`, anything else unknown 404, and a legacy `?ref=` link 301s to `listingUrl()`. Browse pages ("hubs", `listingHubs()` in `lib/Listings.php`) list one type + deal (+ area) hub's listings with breadcrumbs (area hubs through their type + deal hub) and links to related hubs; a hub under `HUB_MIN_LISTINGS` renders `noindex, follow` without canonical/`og:url`. The index links every indexable hub ("Browse by type and area") and a listing links "More …" to its area hub when indexable, else its type + deal hub. `listings-sitemap.php` (`/sitemap-listings.xml`, listed in `robots.txt`) is the live `<urlset>` of those listing URLs plus every indexable hub, with `lastmod` (a hub's = its newest listing's). `inquire.php` adds a Drive-folder link to the staff email when the `property` field carries an `APR-XXXXXX` listing ref. Enterprise-scoped blogs/careers/services return only that enterprise's rows (empty when it has none).
- Blog crawler pages: `blog-page.php` (rule 0 serves it to bot user agents on the apex at `/blogs` and `/blogs/{slug}`) renders, into the same `index.html` shell shape as `properties-page.php`, the index (`<h1>Blogs & News</h1>`, every published post linked with company, date and excerpt; the SPA list's head) or one published post (`?slug=`, `[a-z0-9-]+`): the head of `src/lib/blogSeo.ts` exactly (title `<title> | <company>`, description, canonical `https://alphapremiergroup.com/blogs/{slug}`, cover as OG image, `BlogPosting` + `BreadcrumbList`), then breadcrumbs, `<h1>`, company · date · read time, cover, the body converted like `components/BlogBody.tsx` (admin text, never HTML: only `p h2 h3 ul li strong em` come out, every text run escaped) and 3 related posts (same company first). Company names come from `COMPANIES` in `lib/CrawlerPage.php` (corporate/unknown = Alpha Premier Group). An unknown/draft/malformed slug is 404 `noindex`; an unreadable database is 503 `noindex` with `Retry-After`. `blogs-sitemap.php` (`/sitemap-blogs.xml`, listed in `robots.txt`) is the live `<urlset>` of every published article URL with `lastmod` = `updated_at` (503 when the database is down).
- Job crawler pages (Google for Jobs): `careers-page.php` (rule 0 serves it to bot user agents on the apex at `/careers` and `/careers/{id}-{slug}`) renders, in the same shell shape, the index of active openings or one opening with the head of `src/lib/jobSeo.ts` exactly (canonical `https://alphapremiergroup.com/careers/{id}-{slug}`, `JobPosting` JSON-LD: employment type from `type`, hiring organization, HQ address for Ortigas/Pasig locations, `directApply`). A wrong slug 301s to the canonical URL, a closed opening is 410 `noindex`, an unknown id 404, an unreadable database 503. `lib/JobPages.php` holds the shared URL/row/JSON-LD builders; the hiring organization's name and logo come from `COMPANIES` in `lib/CrawlerPage.php` (corporate/unknown = Alpha Premier Group of Companies). `jobs-sitemap.php` (`/sitemap-jobs.xml`, listed in `robots.txt`) lists every active opening with `lastmod` = `updated_at`.
- Public submission routes are POST-only: `applicants.php` and `inquire.php`. Uploads are capped at 15 MB with an extension allowlist (`pdf doc docx rtf txt png jpg jpeg`).
- `schema.sql` defines `content_blocks`, `service_items`, `job_openings`, `blog_posts`, `job_applicants` (incl. `ats_*` columns), `admins`, `listings`, `listing_images`, `chat_sessions`, `chat_messages`. `setup.php` runs the schema, writes a deny-all `uploads/resumes/.htaccess`, and creates the first admin only from `ADMIN_DEFAULT_PASSWORD` (min 12 chars, no fallback). `migrate.php` is the idempotent cross-enterprise migration/seed backfill, safe on production with admin-edited content: schema changes are guarded; seed backfills (blogs, jobs, services, 88 Prime catalog per kind) are insert-only and run once per database, recorded in the `migration_seeds` ledger (a step whose seed keys already exist counts as done), so edited, renamed or deleted seeded rows are never rewritten or re-created; one-off corrections (Virtual Office seed prices, Dynamic Tree image paths, the old `OPERATIONS` blog category) touch only rows still holding the exact old value and also run once. All three are dev/one-shot tools; `tools/hostinger-update.sh` strips them from production.
- Content registry: `data/content-schema.json` (pages → sections → typed fields with defaults; also bundled into the SPA) + `lib/ContentRegistry.php` (save validation, `inquiryInbox($slug)`/`hrInbox($slug, $fallback)` from the private `_private` page, `siteContactEmail()`/`siteContactPhone()`, same precedence as the SPA `companyContact()`). Consumers: `admin/content.php`, `inquire.php` `inquiryRecipient()`, `lib/Ats.php` `atsHrEmail($slug)`, `lib/email-themes.php` (visible `inbox` + `phone`). Visitor-facing emails show and Reply-To only the public `inbox`, never a `_private` address.
- `.htaccess` denies `*.sql` and `*.md`; `lib/`, `cron/`, and `data/` each carry a deny-all `.htaccess`.

## Flow

1. Each endpoint requires `config.php`; DB-backed handlers also require `db.php` and call `getDbConnection()`. Responses exit through `sendJson()`.
2. Public reads build bound WHERE clauses from validated parameters (`slug`, `enterprise`, `category`, `page`, listing type aliases/search/pagination) and decode JSON list columns before returning.
3. `applicants.php` parses JSON or multipart, runs `guardPublicFormSubmission()`, resolves the enterprise slug, validates fields and the resume (saved under protected `uploads/resumes` with a random name), links `job_id` to a real `job_openings` row (submitted id if it exists, else case-insensitive title match preferring same enterprise/active), inserts `job_applicants`, then registers a shutdown function that flushes the response, runs `atsScreenSafely()` from `lib/Ats.php` (which emails HR immediately with the score and resume; `atsNotifyUnscored()` when scoring fails, or `atsNotifyHr()` straight from the form when the database is down) and sends the applicant a branded confirmation.
4. `inquire.php` performs the same form guard/validation, resolves the enterprise theme (`lib/EmailTemplate.php`), verifies an `APR-XXXXXX` listing ref against `data/listings.generated.json` (real title + Drive-folder link), stores the submission in `inquiries` (kind inquiry | listing | newsletter | feedback | application_question | payment; newsletter rows deduped per email, `updated_at` bumped) before any mail so a lead survives an SMTP failure, emails `inquiryRecipient($slug)` (private setting, else `MAIL_TO_EMAIL`; Reply-To visitor, optional allowlisted attachment) and, after the response, a branded confirmation to the visitor (contact row = Site settings email + phone; Reply-To = public company email). Requests rejected by the form guard, validation or upload checks are never stored. `form=payment` (the Pay Online page, `/pay`) additionally requires a positive peso `amount`, a `payment_method`, a `service` (what the payment is for) and the proof file (`attachment`, JPG/PNG/PDF only); the team email carries amount, channel and reference number with the proof attached, and the visitor confirmation repeats only the validated amount (no review ask). The `inquiries.kind` value `payment` reaches production through `lib/DataFixes.php` (`fix:inquiry-kind-payment`).
5. Admin, visitor chat, and the ATS retry job use `api/admin/`, `api/chat/`, and `api/cron/`; see those maps.

## Integration

- The SPA consumes `/api/blogs|careers|content|listings|services|applicants|inquire.php`; the admin app consumes `/api/admin/*.php`; the chat widget consumes `/api/chat/*.php`. The root `.htaccess` also serves these without the `.php` suffix.
- `applicants.php`, `inquire.php`, and `chat/message.php` require `lib/Mailer.php`; `applicants.php` lazily requires `lib/Ats.php`; `chat/message.php` requires `lib/Gemini.php` and reads `data/knowledge.md`.
- `api/admin/` shares `config.php` RBAC/session helpers, `db.php`, and the CMS/ATS tables; `api/chat/` shares `chat_sessions`/`chat_messages`/`admins` with `api/admin/chat.php`.
- Production lacks a migration runner: `jobSchemaEnsure()` (lib/JobSchema.php) adds missing post-launch columns to `job_openings` (`require_photo`, `ask_portfolio`) and `job_applicants` (`ats_*`, photo/portfolio, interview and decision fields) at runtime (public `careers.php` calls it only after a missing-column error).
